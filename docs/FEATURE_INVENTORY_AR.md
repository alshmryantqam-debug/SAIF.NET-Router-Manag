# NOVA — الجرد الوظيفي للميزات

> **الحالة:** جرد أولي مبني على الشيفرة ومسارات التنقل، وليس اختباراً كاملاً على راوتر فعلي. لا تُحذف أي ميزة خلال الجرد. لا نعتبر وجود شاشة أو Route دليلاً على أن الوظيفة تعمل.

## تعريف التصنيفات

- **تعمل فعلياً:** يوجد تنفيذ واضح ويمكن إثبات النتيجة باختبار آلي أو اختبار تكاملي موثق.
- **تعمل جزئياً:** توجد خدمة/منطق حقيقي، لكن التغطية أو الربط أو التعامل مع الأخطاء غير مكتمل.
- **واجهة فقط:** الشاشة موجودة، لكن البيانات/النتائج تجريبية أو لا يوجد تنفيذ حقيقي للوظيفة المطلوبة.
- **غير مربوطة:** لا يوجد ربط صالح بين عنصر الواجهة ومسار/خدمة، أو المسار/التنفيذ المطلوب غير موجود.
- **قيد التحقق:** حالة مؤقتة ضمن الجرد؛ لا نستنتج النجاح أو الفشل قبل فحص الشاشة والخدمة والاختبارات. بعد الفحص تُحوّل إلى واحدة من الحالات الأربع أعلاه.

## ملخص تنفيذي أولي

| المجال | الموجود في المستودع | الحالة الأولية |
|---|---|---|
| الاتصال بـ RouterOS REST | عميل Dio لـ REST، مصادقة، معالجة أخطاء، موارد النظام وPPPoE النشط وPing | تعمل جزئياً — يحتاج اختباراً تكاملياً على RouterOS 7 |
| RouterOS Binary API | ملف خدمة مستقل موجود | قيد التحقق — لم يُثبت بعد توافقه end-to-end مع RouterOS 6 |
| تسجيل الدخول/ملفات الراوتر | شاشات تسجيل دخول وإدارة راوتر وخدمة تخزين | قيد التحقق — يجب إثبات حفظ الأسرار بأمان وتدفق الاتصال |
| لوحة NOVA | شاشة dashboard ومسارات لمؤشرات الشبكة والاختصارات | تعمل جزئياً/قيد التحقق — اختبار البيانات الحقيقية وحالات الخطأ مطلوب |
| PPPoE وHotspot والقسائم | شاشات وقوائم ومسارات إضافة/إدارة | قيد التحقق — يلزم فحص كل CRUD وربطه بخدمة الراوتر |
| الواجهات وحركة المرور | شاشات interfaces وlive traffic | قيد التحقق — لا تُعتمد الرسوم الحية دون مصدر counters حقيقي وتحديث متكرر |
| PCC / موازنة WAN | معالج مستقل ومسار وأداة ضمن المركز | قيد التحقق عالي الخطورة — لا يُطبّق على الراوتر قبل مراجعة preview/backup/rollback |
| Firewall وTerminal | شاشات ومسارات لأوامر الإدارة | قيد التحقق عالي الخطورة — تحقق من صلاحيات الأوامر ومعاينة التنفيذ |
| الصحة والتنبيهات | Router health analyzer واختبارات وحدات موجودة | تعمل جزئياً — منطق محلي موجود، وتكامل البيانات الحية يحتاج إثباتاً |
| الرادار والسونار وهندسة الشبكة | شاشات منفصلة ومسارات موجودة | قيد التحقق — نفصل القياس الحقيقي عن الرسوم التوضيحية |
| الذكاء الاصطناعي والأتمتة ونواة NOVA | شاشات ومسارات | واجهة/قيد التحقق — لا يُفترض وجود محرك مستقل أو تنفيذ آلي لمجرد الاسم |
| النسخ الاحتياطي الكمي | شاشة ومسار | قيد التحقق — يلزم إثبات إنشاء ملف واستعادته وتشفيره، لا مجرد عرض شاشة |
| الفوترة والأدوار وبوابة العميل | شاشات أعمال ومسارات وحراسة أدوار | قيد التحقق — يلزم اختبار التخزين والصلاحيات والبيانات |
| CloudLink/WireGuard وإعادة تشغيل الراوتر من لوحة التحكم | اللوحة تعرض رسالة صريحة بأن هذه العمليات غير متاحة/غير مربوطة في هذا الفرع | غير مربوطة من لوحة التحكم حالياً؛ لا تُرسل أوامر بهذه الأزرار |

## خطوات التنفيذ

1. تثبيت جرد الملفات والمسارات، ثم مقارنة كل عنصر في مركز الأدوات مع `app_router.dart`.
2. لكل ميزة، تتبّع سلسلة: عنصر UI → route → screen → provider/service → API/model → اختبار.
3. وضع حالة واحدة من الأربع بعد جمع الدليل، مع رابط/اسم الاختبار أو موضع التنفيذ.
4. إصلاح الروابط المفقودة أولاً دون حذف الشاشات أو الملفات؛ ثم إكمال الخدمات والاختبارات.
5. إضافة اختبارات وحدات وواجهات وتكامل وفق الحاجة؛ نجاح التحليل أو البناء وحده لا يثبت عمل الراوتر فعلياً.
6. اختبار أي تغيير على راوتر مختبري/نسخة إعدادات معزولة أولاً. لا تغييرات على CCR2116 الإنتاجي خلال مرحلة الجرد.
